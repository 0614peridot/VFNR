# Virtual Ford Nuclear Reactor 2.0
 WebXR Learning Experience Project Brief

## 1. Project Overview
### 1.1 Goal
- Transform an existing immersive VR learning application ‘Virtual Ford Nuclear Reactor FNR’ into an accessible WebXR learning experience that can reach a broader online audience.
- The FNR VR application was originally developed in Unreal Engine 4.27 for the HP Reverb headsets. Rather than simply reproducing the existing VR application, the project team will reimagine the experience for web, mobile, and non-XR contexts, using the original application and its content as a starting point.
- The experience should support immersive VR/MR/AR where available while gracefully degrading to non-XR devices, including desktop computers, tablets, and mobile phones.
The project will also explore whether immersive and interactive learning experiences can provide meaningful value in an online learning context. The team will establish  measurable usability and engagement criteria that could support a future impact study.

### 1.2 Target Audience
The initial audience is general online learners and prospective students. 
The team should develop appropriate user personas and use them to guide design decisions.
This can be updated depends on the user research and interviews. So keep it open

## 3. Project Scope & Constraints
### 3.1 Required
The final experience must:
- Be based on the existing CAI Unreal Engine VR application ‘Virtual Ford Nuclear Reactor’.
- Reimagine, rather than simply reproduce, the original experience for web-based learning.
- Support Meta Quest 3 and Samsung Galaxy XR.
- Support desktop, tablets and mobile web browsers when a headset is not available.
- Provide an immersive XR experience where supported.
- Provide a usable non-XR experience on unsupported devices.
- Use existing project assets available through Perforce.
- Optimize existing 3D assets for web delivery using Blender/Photoshop or other appropriate tools.
- Define clear learning objectives for the redesigned experience.
- Define measurable usability, engagement, and/or technical success criteria.
- Validate design and prototype decisions through user testing.
- Produce a working prototype by the end of Semester 1.
- Produce a publicly accessible, production-ready experience by the end of Semester 2.
- Regularly document your work and share status updates on the XR Intranet Project Page.


### 3.2 Constraints
- No new 3D assets, existing 3D assets may be modified, optimized, retextured, or otherwise prepared for web delivery.
- The team must consider performance, accessibility, device limitations, loading times, and network conditions.
- The project should remain achievable within the two-semester fellowship period.
- The experience should be front-end only with no backend infrastructure


## 4. Technology
The fellows should independently evaluate the technology stack and justify their choices.
Three.js is the preferred framework, but alternatives such as A-Frame or other appropriate WebXR technologies may be considered when there is a strong technical or design rationale.
Frontend frameworks such as React, Next.js, or Vite may be used when appropriate. 
The team should investigate free hosting options for Semester 1, such as GitHub Pages, Netlify, Vercel, or Cloudflare Pages. University accounts should be used where possible, with appropriate CAI/team access established so the project is not dependent on an individual student's account.
Semester 2 production deployment will use university-provided infrastructure, likely AWS.

## 5. Design & Development Process
The following represents the expected process:

Discover → Define → Ideate → Prototype → Test → Iterate → Develop → Validate → Deploy

The team should:

- Understand the original VR experience, content, users, and learning goals.
- Have one meeting with the faculty to clarify original learning objectives, success criteria and impact.
- Revisit and redefine learning objectives for the new experience.
- Develop user personas and identify user needs.
- Establish project scope and success criteria.
- Brainstorm and conduct design/ideation sessions.
- Develop user journeys, flows, and interaction concepts.
- Create low-fidelity prototypes and validate concepts.
- Develop high-fidelity/functional prototypes.
- Conduct user testing and iterate.
- Implement the final experience.
- Test across supported XR, desktop, and mobile devices.
- Optimize performance and accessibility.
- Deploy and document the final product.

The fellows are responsible for developing their own detailed project timeline and task plan based on this process.
You will have bi-weekly project update check-ins with your supervisor. You have to provide status updates weekly by updating your progress on the XR Intranet Project Page.

## 8. User Testing
User testing should be used to validate design decisions and identify usability problems. The fellows are responsible for recruiting appropriate participants.

### Potential Participants
Potential participants include:

- CAI staff
- CAI student fellows
- Approved students/class participants (supervisor approved)
- Other appropriate university participants (supervisor approved)

Testing should be conducted with users representative of the intended audience whenever possible.
For participants who are not already authorized to enter CAI office spaces, the fellows must coordinate with the supervisor before scheduling in-person testing.

## 9. Definition of Done
The project is successful when the team has demonstrated that it can:

- Translate an existing immersive VR experience into an appropriate WebXR learning experience.
- Make deliberate design decisions based on users and learning objectives.
- Demonstrate those decisions through prototypes and user testing.
- Deliver a functional experience across the required device categories.
- Define and evaluate meaningful success criteria.
- Produce a maintainable, documented, production-ready MVP that can be deployed by another team.
- Clearly communicate the project's design, technical decisions, testing results, limitations, and opportunities for future development.
